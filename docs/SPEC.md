# Ttemp 仕様書

macOS 向け常駐型の一時テキスト／画像置き場アプリ。

本ドキュメントは実装前のヒアリングで確定した全決定事項をまとめたもの。
**実装セッションでは本書を唯一の仕様の根拠とする。** 未決事項は末尾の「未決事項」に集約してある。

---

## 0. 概要

左右 Shift キーの同時押しで、どこからでもプレーンテキスト入力ウィンドウを呼び出せる。
書いた内容はウィンドウを閉じると自動でクリップボードにコピーされる。画像を貼れば画像置き場としても使える。
アプリを終了しても、開いていたウィンドウの配置と内容は次回起動時に復元される。

---

## 1. アプリの形態とライフサイクル

| 項目 | 決定 |
|---|---|
| Dock アイコン | **なし**（`LSUIElement = true` / `NSApplication.setActivationPolicy(.accessory)`） |
| 常駐 | メニューバーアイコンで常駐。ウィンドウが0枚でもプロセスは生存 |
| アプリの終了 | メニューバー右クリックメニューの「Ttemp を終了」のみ |
| `⌘Q` | **割り当てない**（後述の理由） |
| ログイン時の自動起動 | **デフォルト ON**。初回オンボーディング画面でチェックボックスを明示表示した上で有効化。設定からいつでも変更可（`SMAppService.mainApp`） |
| 多重起動 | 2つ目のインスタンスは即終了し、**既存インスタンスが「全ウィンドウを前面に」を実行**する |

**`⌘Q` を割り当てない理由**: 「ウィンドウを閉じる（⌘W）＝クリップボードにコピー」と「アプリを終了＝コピーしない・内容を保存」は挙動が大きく異なる。隣接キーでの誤爆を避けるため、終了はメニューバーからの明示操作のみとする。

## 2. 起動トリガー（左右 Shift 同時押し）

### 判定ルール（リリース発火方式）

**シーケンスは、Shift が1つも押されていない状態からいずれかの Shift が押下された時点で開始する。** 以下を**すべて**満たしたときにのみ新規ウィンドウを生成する。

1. シーケンス中に左 Shift と右 Shift の**両方が押下状態**になった
2. **シーケンス開始から両方の Shift が離されるまでの間**に**他のキーが一切押されなかった**（`A`〜`Z` 等の通常キーを含む）
3. 同じ期間に**他の修飾キーが押されなかった**（`⌘` `⌥` `⌃` `CapsLock` `Fn`）
4. 同じ期間に**マウスボタンが押されなかった**（左・右・中ボタンいずれも）
5. 両方の Shift が離された

### 細則

- 左右を**厳密に同時に押す必要はない**。片方を押している間にもう片方を押せば成立する
- **フロントにあるアプリが何であっても有効**（全画面アプリ上でも動作する）
- 条件2〜4のいずれかが破られた時点でそのシーケンスは無効化され、**すべての Shift が離される**まで再判定しない
- 無効化チェックの起点を「両方が押下状態になった時点」ではなく「最初の Shift 押下」にするのは、**「左 Shift を押しながらタイプ → 右 Shift に指が触れる → 両方離す」という誤爆経路を塞ぐため**。副作用として「Shift+A をタイプした後、その Shift を離さずに両押しする」操作は発火しないが、一度すべての Shift を離せば次のシーケンスで発火できる
- 条件3は**「そのキーが押された」イベント（`flagsChanged` の変化）で判定する**。CapsLock が既に ON（ロック状態）であること自体は無効条件にしない（状態フラグで判定すると CapsLock 常用環境では永久に発火しなくなる）

**マウスボタンも無効条件に含める理由**: 両 Shift を押しながらのクリック（範囲選択など）の最中に、誤って新規ウィンドウが生成されるのを防ぐため。`CGEventTap` の監視対象に `leftMouseDown` / `rightMouseDown` / `otherMouseDown` を含める必要がある。

### この方式を採る理由

Shift は修飾キーであり、「単独で押して離す」という操作は通常のテキスト入力では発生しない。押下即発火（両 Shift が揃った瞬間に起動）だと、`⇧` を押しながらの入力中に反対側の Shift に指が触れただけで誤爆し、しかも発火後にキャンセルできない。リリース発火なら「押しながらのタイプ」を構造的に除外できる。

## 3. ウィンドウの基本挙動

### 3.1 新規ウィンドウの生成

- 左右 Shift の発火時、**アプリをアクティブ化（`NSApp.activate`）した上で新規ウィンドウをキーウィンドウにする**
  - 他アプリで作業中に呼び出す前提のため、アクティブ化しないとウィンドウが出ても文字が打てない
  - これは**新規生成時のみ**の挙動であり、起動時の状態復元では**アクティブ化しない**（§10.3）
- 生成と同時にテキスト入力にフォーカスが当たり、即座に打ち始められる

### 3.2 フォーカスアウト時の挙動

| ウィンドウの状態 | フォーカスアウト時 |
|---|---|
| **空**（後述の定義） | **内容ごと破棄して消える。クリップボードは一切変更しない** |
| **テキストが入っている** | **何も起きない**。ウィンドウはそのまま残り、クリップボードへのコピーも発生しない（コピーは「閉じる」操作でのみ発生する） |
| **画像が入っている** | **空ではないため消えない**。テキストが入っている場合と同じ扱い |
| **最前面固定（ピン留め）されている** | **空であっても消えない**（後述） |

**「空」の定義と判定**

| 論点 | 決定 |
|---|---|
| 「空」の定義 | **テキストモードであり、かつ前後の空白・改行を trim して0文字**（スペースだけ／改行だけの状態も空とみなす） |
| 画像モードのウィンドウ | **常に「空ではない」**。テキストの有無で判定しない |
| 判定タイミング | **フォーカスアウトした時点の内容のみ**で判定。入力履歴は見ない（一度書いて全部消した場合も空として消える） |
| 「フォーカスを外す」の範囲 | **そのウィンドウがキーウィンドウでなくなった時点**。他アプリへの切り替えだけでなく、**Ttemp の別ウィンドウをクリックした場合も含む** |

**ピン留め中は空でも消えない理由**: 最前面固定は「このウィンドウを残す」という明示的な意思表示であり、自動消滅と正面から衝突する。ピン留めしたウィンドウを消したい場合は、固定を解除するか明示的に閉じる。

**キーウィンドウ基準にする理由**: 左右 Shift で新規ウィンドウを開いた瞬間に、古い空ウィンドウが自然に片付く。他アプリ基準にすると空ウィンドウが積み上がる導線が生まれてしまう。

### 3.3 ウィンドウレベルと Spaces

- **基本は通常ウィンドウレベル**（他アプリを前に出すと背後に隠れる）
- **右クリックメニューから「最前面に固定」をトグルできる**（ウィンドウ単位の属性。状態として保存される）
- **Spaces は開いた Space に固定**（別 Space へ追従しない。`collectionBehavior` に `.canJoinAllSpaces` を付けない）
  - ただし**アプリ再起動をまたぐ復元は現在の Space に出る**（ウィンドウを特定 Space に配置する公開 API が macOS に存在しないため。技術的制約として受容）

### 3.4 隠れたウィンドウの呼び戻し

Dock アイコンがないため `⌘Tab` に現れない。以下の2経路を用意する。

- **メニューバーアイコンを左クリック** → アプリをアクティブ化し、**全ウィンドウを前面に**持ってくる（最前面固定していないウィンドウも一時的に前へ）
- **メニューバーアイコンを右クリック** → メニューを表示（ウィンドウ一覧から個別に選べる。詳細は §8.3）

### 3.5 ウィンドウの外観と操作

| 項目 | 決定 |
|---|---|
| タイトルバー | **透明化**（`titlebarAppearsTransparent = true` / `titleVisibility = .hidden` / `.fullSizeContentView`）。タイトル文字は表示しない |
| 信号機ボタン | **閉じるのみ有効**。最小化・ズームは無効化（Dock アイコンがないため最小化すると復帰不能になる） |
| 閉じる操作 | 閉じるボタン / **`⌘W`** / **`Escape`** |
| Escape の例外 | **日本語 IME の変換中・未確定文字がある間は無効**（`hasMarkedText()` が true の間は IME に処理を委ねる）。**find bar 表示中は find bar を閉じるだけ**でウィンドウは閉じない（もう一度 Escape を押すとウィンドウが閉じる） |
| リサイズ | 可能（端ドラッグ） |
| 移動 | タイトルバー領域に加え、**背景ドラッグでも可**（`isMovableByWindowBackground = true`） |
| 背景 | **不透明**。システムのライト／ダークに自動追従（半透明にすると可読性が落ちるため採用しない） |
| 内側余白 | 上下左右 12pt 程度 |
| 角丸 | macOS 標準のウィンドウ角丸に従う |
| 非アクティブ時 | **見た目を変えない**（薄くすると読み返せなくなる） |
| 最前面固定中の表示 | **透明タイトルバーの右端に小さなピンアイコンを常時表示**。クリックで固定解除もできる |

### 3.6 出現位置とサイズ

- **出現位置**: マウスカーソルがあるディスプレイの**中央やや上**
- **重なり回避**: 既存ウィンドウと位置が重なる場合、**右下に 24px ずつカスケード**。画面端に達したら折り返す
- **デフォルトサイズ**: **常に固定 480×320**（手動リサイズしたサイズは次回以降に引き継がない）

**中央固定にする理由**: 出現位置が毎回一定なので視線を動かさずに書き始められる。カーソル位置に出すと毎回違う場所に現れ、目で探す必要が生じる。

### 3.7 アニメーション

| 場面 | 挙動 |
|---|---|
| 新規ウィンドウの出現 | 0.12秒程度のフェードイン（拡大縮小は伴わない） |
| 空ウィンドウの自動消滅 | 0.12秒のフェードアウト |
| `⌘W` / `Escape` / 閉じるボタン | 0.12秒のフェードアウト |

瞬時に消えると「消えたことに気づかない／バグに見える」。0.2秒を超えると軽快さを損なう。

### 3.8 ウィンドウ数

**上限なし**。空ウィンドウは自動消滅するため、増えるのはユーザーが意図的に内容を書いた場合のみ。

## 4. クリップボードへのコピー

**ウィンドウを閉じると、その内容が自動でクリップボードにコピーされる**（テキストならプレーンテキスト、画像なら画像データ）。

### 境界ケース

| ケース | 挙動 |
|---|---|
| 空のウィンドウを閉じた | **クリップボードを一切変更しない**（空文字で上書きすると直前にコピーした内容が失われるため） |
| アプリ本体を Quit した | **コピーしない**。Quit は「閉じる」ではなく「保存して次回復元」。複数ウィンドウがある場合にどれをコピーするか決められない点でも整合的 |
| フォーカスアウトしただけ | **コピーしない**（§3.2）。コピーは「閉じる」操作でのみ発生する |
| 複数ウィンドウを連続で閉じた | **後勝ち**（最後に閉じたものがクリップボードに残る）。マージや連結はしない |
| コピーされたことの通知 | **なし**（無音・無通知。閉じるアニメーションのみ）。1日に何十回も発生する操作なので通知は苦痛になる |

### 閉じた後のフォーカス

**閉じる操作の開始時（`close()` より前）に、Ttemp の次に前面へウィンドウを出しているアプリを画面のZ順（`CGWindowListCopyWindowInfo`、レイヤー0の通常ウィンドウのみ）から求め、`NSRunningApplication.activate()` でフロントに出す。** Ttemp の他のウィンドウ（ピン留め等）が残っている場合も同様にフォーカスを譲る（残ったノートにキーが移ると、閉じる → ⌘V の流れで別のノートに貼ってしまう事故が起きるため）。

- **記憶方式（直前のフロントアプリを覚えておく）は採らない**: ノートを開いたまま他のアプリを行き来する使い方では記憶が古くなり、無関係なアプリが前面に出る
- **`close()` の後に activate する方式は採らない**: キーウィンドウ消滅時に WindowServer が任意のアプリへ一瞬フォーカスを渡すため、無関係なウィンドウがちらつく。閉じる前にこちらから譲れば遷移は1回で済む
- `NSApp.hide(nil)` 方式も採らない（アプリの全ウィンドウが隠れるため、ピン留め等で残したウィンドウまで見えなくなる）
- 復帰先が見つからない場合（他アプリのウィンドウが1枚もない等）は何もしない
- 空ウィンドウの自動消滅（§3.2）ではフォーカス操作を行わない

## 5. テキストモード

### 5.1 入力と表示

| 項目 | 決定 |
|---|---|
| フォント | **システムフォント**（SF Pro / ヒラギノ）。初期サイズ 14pt |
| 折り返し | あり。横スクロールなし。縦は必要時のみスクロール |
| 文字数制限 | なし |
| Enter | 常に改行 |
| Tab | **タブ文字を挿入**（フォーカス移動先が他にないため） |
| Undo / Redo | `⌘Z` / `⇧⌘Z` 対応。**ウィンドウを閉じたら履歴は破棄** |
| 検索・置換 | **対応**。`⌘F` で検索、`⌘⌥F` で置換（`NSTextView` 標準の find bar を使用） |

### 5.2 macOS の自動処理 — すべて OFF

- スマートクォート（`"` → `"`）
- スマートダッシュ（`--` → `—`）
- 自動大文字化
- 自動スペル修正
- テキスト置換
- スペルの赤波線表示
- **リンクの自動検出**（`isAutomaticLinkDetectionEnabled = false`）
- **データ検出**（日付・住所等の自動リンク化。`isAutomaticDataDetectionEnabled = false`）

「入れたものがそのまま出る」ことが保証されるべきであり、勝手に引用符が全角化してコードが壊れるのは致命的。一時メモに校正機能は不要。

**リンクの自動検出を切る理由**: §5.3 でペースト時にリンク属性を削除すると決めているが、これを OFF にしないと**入力側で URL を打った瞬間に自動でリンク属性が付与され**、同じルールが破られる。

### 5.3 ペースト時の書式剥がし

外部からペーストした内容は**すべてプレーンテキスト化**する。

**剥がすもの**
- フォント、サイズ、色、太字／斜体／下線、背景色などの**全テキスト属性**
- 段落スタイル（行間、インデント、揃え）
- リンク（**URL の文字列だけ残す**。リンク属性は削除）
- 添付ファイル・インライン画像（HTML や RTFD に画像が混在していた場合、**テキストだけ取り出して画像は捨てる**）

**保持するもの**
- **タブ文字**（インデント構造は情報なので残す）
- 全角スペース・絵文字・あらゆる Unicode 文字
- 連続する空行

**正規化するもの**
- **改行コードを LF に統一**（CRLF / CR → LF）
  - `NSTextView` の内部表現が LF のため CRLF の保持自体が困難であり、Windows 由来のテキストで不可視の CR が混入するとコピー先（ターミナル、コードエディタ）で実害が出る

### 5.4 ペースト内容の判定順

クリップボードに複数形式が含まれる場合、以下の順で判定する。

1. **ファイル URL がある** → それが画像ファイルなら画像モード（**ウィンドウが空の場合のみ**）、画像以外のファイルなら拒否（§6.3）。**ファイル URL がある場合、pasteboard 上の画像データは見ない**（Finder はファイルコピー時にアイコン画像を pasteboard に載せることがあり、PDF 等のコピーがアイコン絵で画像モードになる誤判定を防ぐ）
2. **画像データがあり、かつプレーンテキスト型が pasteboard に存在しない** → 画像モード（同上）
3. それ以外 → **プレーンテキストとして挿入**

**「画像＋プレーンテキスト」が混在する場合は常にテキストを優先する。** 混在ペーストの意図はほぼ常に文章側にあり、意図せず画像モードになって入力不能になる方が事故として大きい。なお、ブラウザの「画像をコピー」は通常プレーンテキスト型を含まない（画像データ＋HTML のみ）ため、この規則でも期待どおり画像モードになる。

## 6. 画像モード

### 6.1 モードの遷移

| 状況 | 挙動 |
|---|---|
| **空のウィンドウ**に画像をペースト／ドロップ | 画像モードに移行。テキスト入力は不可になる |
| **文字が入っているウィンドウ**に画像をペースト／ドロップ | **拒否**（ウィンドウを軽く横に揺らす拒否フィードバックのみ。テキストは無傷） |
| 画像モード中にさらに**画像**をペースト／ドロップ | **置き換え**（1ウィンドウ1枚を保つ唯一の方法） |
| 画像モード中に**テキスト**をペースト | **拒否**（同じシェイクのフィードバックのみ）。テキストを入れたい場合は先に画像を削除する |
| 右クリックメニューから「画像を削除」 | **空のテキストモードに戻る**。ウィンドウは残り、そのまま文字入力できる（フォーカスを外せば空なので消える） |

**「空のときだけ受け付ける」理由**: 無警告の破壊的操作は論外であり、確認ダイアログはこのアプリの軽快さと正面から衝突する。「画像は空のウィンドウにしか入らない」という一行のルールで説明でき、拒否された事実もその場で分かる。

### 6.2 画像の表示

- ペースト時に**ウィンドウを画像サイズに合わせてリサイズ**する
- **サイズ計算はポイント基準**。ピクセル数ではなく DPI メタデータを反映した論理サイズ（`NSImage.size`）を使う（Retina の 2x スクリーンショットが物理ピクセル基準の巨大ウィンドウにならないようにする）
- **上限**: そのウィンドウがあるディスプレイの**可視領域の 60% 程度**を超えないよう縮小
- **下限**: ウィンドウが操作不能にならないよう**最小 200×150** は確保。画像はその中央に等倍表示
- **手動リサイズ後**: 画像はアスペクト比を保ってフィット。**レターボックス（余白）で表示し、切り抜きはしない**
  - **拡大はしない**（`NSImageView.scaleProportionallyDown`）。下限サイズの「中央に等倍表示」と整合させるため、ウィンドウを画像より大きくしても画像は原寸のまま中央に置かれる
- **画像を削除してテキストモードに戻った時**: **ウィンドウサイズは元に戻さず、そのまま維持する**

### 6.3 入力経路と対応形式

- **ドラッグ&ドロップ対応**（画像ファイル、ブラウザ上の画像。受付条件は §6.1 と同じ）
- **複数ファイルを同時にドロップした場合**: **最初の画像ファイル1枚のみ**を受け付け、残りは無視（1ウィンドウ1枚の原則を保つ）
- **Finder で画像ファイルをコピー → ペースト**: ファイル URL を解決して**画像として読み込む**（パス文字列としては扱わない）
- **画像以外のファイル**（PDF、.txt、.zip 等）: **すべて無視**（拒否フィードバックのみ）
  - 守備範囲を「プレーンテキスト」と「画像1枚」の2つに限定する。PDF やテキストファイルを足すと境界が際限なく増える
- **対応形式**: macOS 標準（NSImage / ImageIO）が読める形式すべて（PNG / JPEG / HEIC / GIF / TIFF / WebP 等）
- **GIF アニメーション**: **通常は1枚目を静止表示。マウスカーソルをホバーしている間だけアニメーション再生**

### 6.4 巨大画像

- 表示用に画面解像度に合わせて**ダウンサンプリング**（メモリ節約）
- **原本データは必ず保持**（「画像を保存」「画像をコピー」で劣化させないため）

## 7. 文字サイズ

### 7.1 計算モデル

各ウィンドウは**グローバル値からの相対オフセット（±pt）**を持つ。

```
実効サイズ = clamp(グローバル値 + そのウィンドウのオフセット, 9pt, 48pt)
```

- **クランプは表示時のみ適用し、オフセット値自体は保持する**
  （上限に張り付いた後にグローバル値を下げれば、元の相対関係が復活する）
- **グローバル値自体は 9〜48pt の範囲にクランプして保持する**（`⌘;` の連打や設定画面の直接入力で範囲外にならない。オフセットと異なり、範囲外のグローバル値を保持しておく意味がない）
- **ステップは 1pt**
- グローバル値を変更すると、**全ウィンドウが相対関係を保ったまま追従する**
  （例: 小・中のウィンドウがある状態でグローバルを上げると、中・大になる）

### 7.2 キーバインド

| 操作 | グローバル（全ウィンドウ＋今後の新規） | ローカル（そのウィンドウのみ） |
|---|---|---|
| 拡大 | `⌘;` / `⌘⇧;` / `⌘=` | `⌃;` / `⌃⇧;` / `⌃=` |
| 縮小 | `⌘-` | `⌃-` |
| リセット | `⌘0`（**グローバル値を初期値 14pt に**。各ウィンドウのオフセットは維持） | `⌃0`（**そのウィンドウのオフセットを0に**） |
| スクロール | `⌘ + マウススクロール` | `⌃ + マウススクロール` |

- 拡大は `⌘;` `⌘⇧;` `⌘=` の**すべてを受け付ける**（JIS配列では `+` が `;` の Shift 側にあるため。衝突する機能が他にないので排他にする必要がない）
- `⌥;` は macOS 標準では文字入力に使われる打鍵だが、Option をローカル修飾キーに設定した場合はアプリ内で奪う
- **画像モードのウィンドウでは文字サイズ操作は無効**（ウィンドウの端をドラッグすれば拡大縮小が完結しており、独立したズーム状態を持つと「ウィンドウサイズと画像倍率」の2軸管理になる）
- ただし**画像モード中もそのウィンドウのオフセット値は保持される**。画像を削除してテキストモードに戻ると、画像を貼る前の文字サイズで復帰する
- 表内のローカル側の `⌃` は**既定の修飾キーを表す**。設定で Option に変更した場合は `⌥;` `⌥-` `⌥0` `⌥ + マウススクロール` に読み替える（§7.3）。グローバル側の `⌘` は固定

### 7.3 ローカル修飾キーの設定

設定画面で **Control / Option** から選択できる（グローバル操作は `⌘` 固定）。
選択した修飾キーは**スクロールとキーボードショートカットの両方に適用**される。

**既知の制約**: macOS の「アクセシビリティ → ズーム → スクロールジェスチャと修飾キーを使ってズーム」が ON かつ修飾キーが Control の場合、`⌃ + スクロール` は OS 側の画面ズームに奪われアプリまで届かない。この場合は設定で Option に変更するか、キーボード側（`⌃;` / `⌃-`）を使う。

## 10. 永続化と復元

### 10.1 保存タイミング

- **逐次保存**: 内容変更・移動・リサイズのたびに、**1秒程度のデバウンス**でディスクに書く
- **Quit 時にも保存**

Quit 時のみの保存だと、クラッシュ・強制終了・`killall`・システムの予期しない再起動で**全内容が消える**。このアプリは「他で書けない一時的な情報の置き場」なので、消えた時の損失が体感的に大きい。

### 10.2 保存内容と保存先

**ノートの状態** — `~/Library/Application Support/Ttemp/state.json`

- テキスト本文 / 画像（画像は `Images/<uuid>.<ext>` として**原本のバイト列を個別ファイルに保存**し、JSON からは参照のみ）
- ウィンドウの位置・サイズ
- **最前面固定フラグ**
- **ウィンドウ個別の文字サイズオフセット**
- ウィンドウの並び順
- **空ウィンドウは保存対象外**

**アプリ設定** — `UserDefaults`（state.json とは分離する）

- グローバル文字サイズ
- ローカル操作の修飾キー（Control / Option）
- ログイン時に起動
- 画像の前回保存先ディレクトリ
- オンボーディングを表示済みかどうか

分離する理由: 設定はノートの内容と寿命もバックアップ対象としての性格も異なり、state.json が破損した際に設定まで巻き添えで失われるのは望ましくない。

### 10.3 復元時の挙動

- **アプリは非アクティブのままウィンドウだけ表示**し、他アプリのフォーカスを奪わない（ログイン直後に作業を妨害しないため）
- **復元位置は必ず現在の可視領域内にクランプする**
  - 外部ディスプレイを外した状態で起動すると、保存された座標が画面外になり**ウィンドウが操作不能**になるため。いずれの画面にも収まらない位置だった場合はメインディスプレイの中央に配置する
- Space は現在の Space に復元される（§3.3 の技術的制約）

### 10.4 堅牢性

- **保存はアトミック書き込み**（一時ファイルに書いてから rename）。書き込み中のクラッシュで壊れないようにする
- **状態ファイルが壊れていた場合**: 復元を諦めて空の状態で起動し、**壊れたファイルは `state.json.corrupt-<日時>` にリネームして残す**
  （黙って新規状態で起動すると「保存されていたはずのメモが全部消えた」という最悪の体験になり、原因も残骸も残らない）

## 11. システム権限

### 11.1 方式

**`CGEventTap`（listen-only）を使用し、「入力監視」権限を要求する。**

- `NSEvent.addGlobalMonitorForEvents` は**アクセシビリティ権限**を要求するが、これは他アプリの UI を操作できる強い権限であり、キー入力の読み取りしか必要ないこのアプリには過剰
- §2 の判定には `keyDown` とマウスイベントも見る必要があり、`CGEventTap` の方が扱いが素直
- タップが何らかの理由で無効化された場合、アプリ側から再有効化できる（`CGEvent.tapEnable`）

### 11.2 制約

**この権限は App Sandbox 内では取得できない。** したがって:
- **サンドボックスなし**
- **Mac App Store での配布は不可**（直接配布のみ）

### 11.3 権限まわりの UX

| 状況 | 挙動 |
|---|---|
| 初回起動時 | 「なぜ入力監視が必要か」を説明する小さなウィンドウを表示。「システム設定を開く」ボタンで TCC 設定画面に直接遷移。**同画面に「ログイン時に起動」チェックボックス（デフォルト ON）も置く** |
| 権限が未付与／剥奪された場合 | メニューバーアイコンに警告表示。左右 Shift は反応しないが、**メニューバーからの新規ウィンドウ作成は可能**にして機能が完全に死なないようにする |
| 権限付与の検知 | 定期的にチェックし、承認された瞬間に自動でタップを開始。**アプリの再起動を不要にする** |

## 12. 技術スタックと配布

| 項目 | 決定 |
|---|---|
| UI フレームワーク | **AppKit**（`NSTextView` / `NSWindow` / `NSStatusItem` / `NSMenu` を直接操作） |
| プロジェクト管理 | **XcodeGen**（`project.yml` から生成）。ビルドは `xcodebuild` で CLI 完結 |
| 最低対応 OS | **macOS 14.0 (Sonoma)** |
| ビルド SDK | macOS 26 系（最新の外観が自動適用される） |
| Bundle ID | **`com.am921.ttemp`** |
| メニューバーアイコン | SF Symbol **`t.square`**（テンプレート画像でライト／ダーク自動反転） |
| アプリアイコン | **後回し**（暫定でシンプルな単色＋"T"。入力監視の権限一覧等に表示されるため何かしらは必要） |
| Hardened Runtime | **最初から有効化しておく**（後付けすると権限周りの再検証が必要になるため） |

**AppKit を選ぶ理由**: 今回の仕様のほぼ全てが SwiftUI の標準 API の範囲外にある。ペースト時の書式剥がし・自動置換の全 OFF・検索/置換バーは `NSTextView` の直接制御が必須。タイトルバー透明化と信号機ボタンの個別無効化、ウィンドウレベル切替は `NSWindow` 直接操作。メニューバーの左右クリック分岐は `NSStatusItem` 直接操作。SwiftUI + NSViewRepresentable にすると、これら全てをラップした上で SwiftUI 側と AppKit 側で状態を二重管理することになる。

### 配布方針（段階的）

1. **現段階**: ローカルビルドのみ。開発用署名で運用
2. **将来**: Developer ID 署名＋公証（notarize）して `.dmg` で配布

| | Developer ID 署名＋公証 | 未署名 / ad-hoc 署名 |
|---|---|---|
| 初回起動 | 普通にダブルクリックで開く | 「開発元を確認できません」でブロック。macOS 15 以降は「右クリック→開く」の抜け道が塞がれ、システム設定→プライバシーとセキュリティ→「このまま開く」が必須 |
| 入力監視権限 | 再ビルド・アップデートしても**許可が維持される** | 署名が変わるたび TCC の許可が**リセット**され、更新のたびに再承認 |
| 必要なもの | Apple Developer Program（年額 $99） | 不要 |

コード側の対応（Hardened Runtime、entitlements、公証スクリプト）を最初から入れておけば、移行は証明書取得後すぐに済む。

## 13. テスト方針

**純粋ロジックのみ XCTest で書く。UI 挙動は手動確認。**

対象:
- 左右 Shift 判定のステートマシン（他キー混入・修飾キー混入・マウスボタン混入・順不同の押下など分岐が多い）
- 書式剥がし（`PlainTextSanitizer`）
- **ペースト内容の判定順**（`PasteboardReader`。画像／ファイルURL／テキストの優先順は事故が起きやすい）
- 文字サイズの相対計算とクランプ
- 状態のシリアライズ / デシリアライズ（バグると実害＝メモ消失が大きい）
- 出現位置のカスケード計算（画面端の折り返しを含む）
- 復元位置の可視領域クランプ

UI テストを書かない理由: 常駐アプリ＋グローバルホットキーという性質上、環境構築のコストがリターンに見合わない。
